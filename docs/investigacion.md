## Reglas de negocio derivadas

| Regla | Fuente |
|---|---|
| R1. Todo asiento contabilizado cumple Σ debe = Σ haber, con al menos 2 líneas y total > 0. Se valida en el dominio y en la BD (trigger diferido). | #10 (art. 20 LORTI), #4 |
| R2. Cada línea tiene **o** debe **o** haber (> 0), nunca ambos; importes USD con 2 decimales. | #10, #2 |
| R3. Solo las cuentas de último nivel (`accepts_entries = true`) reciben movimientos; las cuentas de grupo se calculan sumando hijas. | #1 (tipo T = total / D = detalle) |
| R4. El código de una cuenta hija empieza con el código de su padre; el primer dígito define el elemento: 1 activo, 2 pasivo, 3 patrimonio, 4 ingresos, 5 costos y gastos. | #1 |
| R5. Naturaleza: activos y gastos son deudores; pasivos, patrimonio e ingresos son acreedores; las cuentas correctoras (signo N en Supercias, ej. depreciación acumulada) tienen naturaleza contraria a su grupo. | #1, #4 |
| R6. Periodo cerrado = inmutable. Un error se corrige con asiento de reverso (espejo exacto) y un nuevo asiento en un periodo abierto. | #8 (párr. 10.21) |
| R7. Ecuación contable: Activo = Pasivo + Patrimonio + (Ingresos − Gastos del ejercicio no cerrado). | #4 (2.15, 2.22) |
| R8. Estado de resultados por función: ingresos ordinarios (41) − costo de ventas (51) = ganancia bruta; + otros ingresos (43) − gastos (52) = ganancia antes de 15 % e IR; − 15 % participación; − impuesto a la renta = ganancia neta. | #2, #7 |
| R9. Estado de situación financiera con activo / pasivo corriente y no corriente (códigos 101/102 y 201/202). | #1, #6 |
| R10. Cierre del ejercicio: asiento de cierre que salda ingresos y gastos contra 30701 (ganancia) o 30702 (pérdida). Los estados de resultados excluyen ese asiento. | #1, #7 |
| R11. Moneda única USD. | #10 |

## Supuestos (no verificados o decisiones propias)

- **SUPUESTO S1** — El catálogo de Supercias es un formato de *presentación* sin raíces "4" ni "5" (empieza en 41 y 51). Para el libro mayor se agregan raíces **4 INGRESOS** y **5 COSTOS Y GASTOS**, práctica común en Ecuador pero no normada en la fuente #1.
- **SUPUESTO S2** — El PDF de Supercias trunca los nombres de 5201 y 5202 ("GASTOS"). Por el instructivo (#2: "gastos de venta, gastos administrativos, gastos financieros y otros gastos") se nombran **5201 GASTOS DE VENTA** y **5202 GASTOS ADMINISTRATIVOS**.
- **SUPUESTO S3** — En el formulario de Supercias, 15 % participación trabajadores (61) e impuesto a la renta (63) están fuera del grupo 5. En el libro mayor se registran como **5301** y **5302** (grupo 53) para mantener la regla "primer dígito = elemento"; el estado de resultados los presenta en su posición del formulario.
- **SUPUESTO S4** — Una empresa por instancia (sin multiempresa) y periodos mensuales.
- **SUPUESTO S5** — Las cuentas de detalle bajo el nivel Supercias (ej. 101010101 Caja general, 101010102 Bancos) son ejemplos para la demo; cada empresa define las suyas (importación CSV).
- **SUPUESTO S6** — Formato de eventos de `facturador-sri` y `nomina-ec`: se define aquí un contrato JSON propio (esos proyectos aún no lo publican). Los montos llegan calculados; esta API no calcula IVA ni aportes IESS.
- **DECISIÓN D-01** — Se pidió Spring Boot 3, pero la línea 3.x ya no recibe parches de seguridad OSS (fin 30-06-2026, fuente #12). Se usa Spring Boot **4.1.1** con Java 25 (LTS).
